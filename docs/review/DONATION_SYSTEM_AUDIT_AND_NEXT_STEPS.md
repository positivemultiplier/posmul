## 2. 냉철한 갭 분석: 무엇이 아직 부족한가? (Gap Analysis)

완성된 UX 뒤편에, **실제 상용 서비스 런칭을 위해 보완해야 할 현실적인 부족한 점 5가지**입니다.

### ① 결제 및 실제 잔고 차감 (Points & Ledger)
* **현재 상태**: 상단 헤더의 모의 잔고(`510,000 PMC`)를 바탕으로 클라이언트에서 차감 시뮬레이션됨.
* **부족한 점**:
  * 사용자의 실제 Supabase DB 지갑(`wallets` 또는 `user_points`)에서 잔고가 원자적(Atomic Transaction)으로 차감되는 백엔드 연동 필요.
  * 기부금 영수증(소득공제/세액공제) 발행을 위한 개인 식별 정보 및 국세청 전산 연계 체계(초기에는 지정기부금단체 협력 위탁 권장).

### ② 수혜시설 고유번호증 파일 업로드 (Document Verification Storage)
* **현재 상태**: 텍스트 입력창으로 고유번호증 번호나 인가번호를 입력받음.
* **부족한 점**:
  * 허위 신청을 100% 거르기 위해 **고유번호증/시설신고증 사본(PDF/JPG)을 Supabase Storage에 업로드**하는 첨부파일 모듈 필요.

### ③ 제조사 발주 파이프라인 (Fulfillment Process)
* **현재 상태**: 100% 펀딩 완료 시 DB 상태가 완료로 바뀌고 축하 배너가 뜸.
* **부족한 점**:
  * 실제로 85만 PMC(85만 원)가 모였을 때 LG전자나 부산 제화에 어떻게 발주를 넣을 것인가?
  * **현실적 해결책**: 초기에는 무리한 API 자동 발주 대신, 관리자 데스크에서 모금 완료된 내역을 **엑셀/공문으로 내려받아 제조사 B2B 특판부에 대량 발주 넣는 수동 오퍼레이션(Concierge MVP)**으로 충분함.

### ④ 기부자 피드백 루프 (Donor Feedback Loop)
* **현재 상태**: 기부 즉시 팝업으로 감사 메시지 노출.
* **부족한 점**:
  * 기부 완료 후 며칠 뒤, 내가 기부한 에어컨이 햇살아동센터에 도착했을 때 **"배송 완료 및 아이들의 감사 사진"**을 기부자에게 어떻게 보여줄 것인가?
  * 내 기부 내역 페이지(`my page / my donations`) 및 알림 기능 필요.

### ⑤ 4대 기부 필러의 단계적 오픈 (Pillar Rollout)
* **현재 상태**: Pillar 1(K-물품 직접기부 & 위시리스트) 집중 구축 완료.
* **부족한 점**:
  * Pillar 2 (마일스톤 NGO), Pillar 3 (의인 포상), Pillar 4 (꿈의 사다리)는 마스터 스펙 문서는 완벽하나 화면은 아직 준비 중.
